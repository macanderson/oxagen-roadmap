    Dialog

    A dialog opens over the page for one task: invite a person, set a budget, approve a schema, retire an agent. It has a header that names the task, a body that holds the fields or the facts, and a footer with Cancel and the one action. On a phone it rises from the bottom edge as a sheet.

    Root .dlg CSS engine.css lines 471 to 490, phone 689 to 701 Used on Work (Intake), Agents, Spend (Set a budget), Organization (Invite a person), Tools, Steering

    Examples

    Each example is the engine's own markup, drawn by engine.css. Open Markup to copy it.

    Anatomy

    Usage

    Use it for
    • A task that needs input before it runs: invite a person, set a budget, connect an issue tracker.
    • A confirm for an action that ends something: retire an agent, remove a budget, revoke a key.
    • A review that compares two sources before a governed action, in the wide shell.
    Use something else for
    • Items waiting on a person across the organization: use the drawer.
    • The result of an action: use a toast.
    • Reading a record: link to its page.
    • A short list of choices: use a menu.

    Are you sure?

    This action cannot be undone.

    AvoidA title that names nothing, a body that says nothing about what ends, two gold buttons, and an OK that could mean anything.

    Revoke key

    Ends
    every call signed with oxk_live_4F2A
    Kept
    the audit record of each use

    UseThe title and the button name the act, and the body says what ends and what is kept.

    • One dialog at a time. A dialog opened from Intake returns to Intake when it closes (S.dlgBack), so the person never loses the step they were on.
    • The footer holds at most one gold button. A destructive action uses .btn.danger and no gold.
    • Cancel comes first and the action last. A review that can wait may say "Not yet" in place of Cancel.

    Content

    • Title: names the task in sentence case: "Invite a person", "Set a budget", "Approve an observed output schema". Never "Are you sure?" or "Confirm".
    • Subtitle: one line, the record the dialog acts on (a-intel.core.triage) or one fact.
    • Action button: the act, and the record where it helps: "Send the invitation", "Approve schema", "Retire agent". Never OK, Submit, Yes, or Done for an action that writes.
    • Destructive confirm: a key-value list that names what is kept, what ends, and what is in flight, and a check card that reads "I understand this cannot be undone" with the consequence under it.
    • Footer note: one sentence that names the governed action the button records, with the action name in mono.
    • Hints: under the field they explain, one or two sentences, in the present tense.

    Accessibility

    • The shell is role="dialog" with aria-modal="true" and an aria-label equal to its title.
    • The close button is labelled Close. Escape closes the dialog, and so does a click on the scrim outside it.
    • Opening moves focus into the dialog, to the first field or the close button. Tab stays inside while it is open. Closing returns focus to the control that opened it. The mockup does not do this yet. See Findings.
    • Every field has a visible label tied to it with for. A disabled danger button says why in the check card beside it.

    Phone

    • The dialog becomes a bottom sheet: full width, an 18px top radius, a 36 by 4px grab handle in --rule, and a rise from the bottom edge (none under reduced motion).
    • The sheet is at most the window height minus 24px, and only the body scrolls.
    • The footer reverses so the action comes first, each button takes half the row at 46px tall, and a footer note takes its own line.
    • Inputs are 16px and 44px tall, and .fields stacks to one column.

    Findings

    openNo focus management

    render() writes the dialog into #layer and moves no focus. Focus stays on the page behind, Tab walks out of the dialog, and closing does not return focus to the opener. A build needs all three.

    fixedRetired term in the retire dialog

    The retire dialog read "Deregister agent" with a Deregister button, a term the copy review retired, and check-copy.mjs never opened it. It reads Retire agent now, the page specs quote it, and check-copy.mjs opens the dialog.

    noteScrim color is fixed

    The scrim is rgba(0,0,0,.68) in both themes (engine.css 471). It follows no token.

    noteTwo footer note idioms

    Most footers use .dlg-f .grow. The schema review writes an inline margin-right:auto span instead (engine.js 9707).

    noteVague action labels

    Set a budget's action reads "Set it" (engine.js 9569). The action names its record elsewhere, as in "Send the invitation".

## Procedure

Record PASS, FAIL, or N/A for every check. Cite evidence for each: a file and line in the build, or a DOM selector with its computed style and text.

1. Shell. Every dialog is one `role="dialog"` element with `aria-modal="true"` and an accessible name equal to its visible title. A dialog without both is a FAIL.
2. Layout. The shell is at most 600px wide (820px for a wide review), on `--panel` with a 1px `--rule` border, a 14px radius, and `--shadow`, 70px from the top of the window, over a scrim with a 3px blur.
3. Header. The title is an h2 at 16px Geist 600. A subtitle is one 12.5px `--muted` line. The close button is last in the header, 32px, and labelled Close.
4. Footer. Buttons are right-aligned with Cancel first and the action last. At most one gold button, and none when the action is destructive. An action labelled OK, Submit, or Yes is a FAIL.
5. Destructive confirm. The body names what is kept, what ends, and what is in flight. The danger button is disabled until the "I understand" check is ticked. A destructive action that runs on one click is a FAIL.
6. Focus. Opening moves focus into the dialog. Tab and Shift+Tab stay inside. Escape and a click on the scrim close it. Closing returns focus to the opener. Any one missing is a FAIL.
7. Return path. A dialog opened from another dialog (Intake to the connection wizard) returns to it on close. Only one dialog shows at a time.
8. Body scroll. A long body scrolls inside the dialog at a 62vh ceiling while the header and footer stay put, and the page behind does not scroll.
9. Tokens. Every color, border, radius, and shadow in the build's version resolves to the tokens listed in the Tokens section of the reference page. A raw hex, rgb, or named color is a FAIL.
10. Type. Text computes to Geist and ids, keys, and code compute to Monaspace Neon, at the sizes and weights the reference page's examples render. Space Grotesk anywhere in the component is a FAIL.
11. Themes. Repeat every visual check in the light theme. A part that loses its border, its contrast, or its meaning in one theme is a FAIL.
12. Phone. At 390 by 844 with a touch pointer: The dialog becomes a bottom sheet: full width, an 18px top radius, a 36 by 4px grab handle in `--rule`, and a rise from the bottom edge (none under reduced motion). The sheet is at most the window height minus 24px, and only the body scrolls. The footer reverses so the action comes first, each button takes half the row at 46px tall, and a footer note takes its own line. Inputs are 16px and 44px tall, and `.fields` stacks to one column.
13. Accessibility. The shell is `role="dialog"` with `aria-modal="true"` and an `aria-label` equal to its title. The close button is labelled Close. Escape closes the dialog, and so does a click on the scrim outside it. Opening moves focus into the dialog, to the first field or the close button. Tab stays inside while it is open. Closing returns focus to the control that opened it. The mockup does not do this yet. See Findings. Every field has a visible label tied to it with `for`.
