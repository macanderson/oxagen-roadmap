# Audit prompt: Agent detail

Copy everything below the line into a fresh agent session. Fill the two placeholders. The agent
audits the built page against this design and reports a verdict per check; it does not fix anything
unless told to in a second turn.

---

You are auditing the **Agent detail** page of Oxagen (`#/a-intel/core-platform/agents/<slug>[/<tab>]`) for conformance to its design. Be exact and adversarial: the design is the spec, and “close enough” is a fail. Do not summarise what you see; compare it.

## Inputs

1. The page spec: `pages/agent.md` (read it first, in full). Read `docs/agent-ontology-ia.md` after it for the object model and the words the page must use.
2. The design, rendered: the `agent` stories in Storybook (`npm run storybook`), one per tab and per state (loaded, empty, loading, error, access denied), desktop and mobile; or `mockups/missioncontrol.html?product=1&state=<state>&mobile=<0|1>#<route>` in a browser or with Playwright. The checker is `node tools/check-mockup.mjs`.
3. The product spec for context: `docs/mission-control-spec.md` §14 (Mission Control), §12.6 (token classes), §12.7 (attribution), §8 (the call pipeline), Appendix F (the pages that survive), Appendix A (target tables); the data mapping in `docs/implementation-plan.md` §3.
4. The build under audit: `{{APP_ROOT}}` (the Next.js app), served at `{{APP_URL}}`. Route under audit: `/a-intel/core-platform/agents/<slug>`.

## Procedure

Work through every check. For each, record PASS, FAIL, or N/A (with why). Cite evidence: a file and line in the build, a screenshot path, or a DOM selector and its text.

1. **Route and shell.** The build serves the route and every tab route; the sidebar (Workspace: Fleet, Agents, Tools, Steering, Runtimes, Repositories, Spend; Organization: Organization, Billing, Audit; the assistant launcher at the foot), breadcrumbs (… / Agents / <agent name>), ⌘K search, notifications, the approvals button, and account are present and match the spec’s shell. No assistant button in the top bar. The document title names the page.
2. **Tabs and aliases.** Eight tabs in order: Overview · Identity · Steering · Toolbelt · Runtime · Permissions · Activity · Definition in git. Each is a route segment and is linkable; back moves between tabs. Live counts: Toolbelt = belt width, Permissions = mandates held, Activity = tamper incidents; a zero renders no badge. Every rev1 id still resolves to the tab that absorbed it: `mandates` → Permissions, `budgets` → Permissions, `runs` → Activity, `incidents` → Activity, `enrollment` → Runtime. An unknown id falls back to Overview.
3. **Header.** Eyebrow “Agent”, h1 the agent card in the detail layout with no score. Badges: status, tier, “replay <grade>”, “operator <name>”; then the description. Actions present, in order, with the same labels: Edit avatar · Rotate credential · Suspend · Deregister. No gold action on this page. No score strip, no auto-approvals note, no proof rate, no business value.
4. **Overview.** 30-day token use: badge “N tok · $ · <basis>”; eight composition bars in order (Conversation, Tool results, Context frames, Tool definitions, Steering, System, Output, Reasoning) each with tokens and share; Cache hit rate · Per run · Per model call · Basis. Coaching: badge “N from the token record”; at most three items, each with a title, a signal line, “$ a month at stake” where there is a figure, and one action button; the empty copy verbatim; the footer link to the workspace’s coaching. Composition: the health badge, then Identity · Steering · Toolbelt · Runtime · Owner · Permissions, each with an Open button to the tab or registry that owns it, and each toolbelt named as a link into Tools → Toolbelts. Last 30 days: Runs · Spend · Tokens · Tamper incidents, with Open activity. Definition in git: Path · Repo · Commit · `definition_digest` · Generated beside it, with Open the file.
5. **Identity.** Identity (Agent key · Principal · Kind · Harness · Model tier · Operator · Lifecycle state · First frame), Credentials (badge “none”; five rows; See the connections that mint them), Run credential (Key · Purpose lock · Issued · Last used · Run tokens · Host device key; Change identity, Revoke credential), Trust relationships (Accountable human · Workspace · Runtime · Delegation · Replay · Tamper incidents; Open its permissions). No roles list and no tier ladder on this tab; both moved. The Cost center row shows the agent's label or "None", **Change**, and the one line of why: the agent's own label, the label inherited from its workspace, or neither. Check one agent of each kind. **Change** opens `ccagent` for an organization Owner, Admin or Billing member, and saving writes `cost_center_set` to Audit. For anyone else it shows a toast that names who holds the role and opens no dialog.
6. **Steering.** On the `observe` tier, the warning bar states that nothing below reaches the agent and why. Two meters: Stable prefix · SessionStart additional context (bytes against the 16 KiB cap) and Volatile selection · token budget (tokens, with the prompt). What reaches this agent: Item · Kind · Force · Scope · Body · Source · Where it lands · Token cost, with Change what is assigned and Open in the compiler. Kind is the Library's kind badge, not a grey chip. Cut for this agent: Item · Kind · Force · Token cost · Cut because · Why. Nothing on this tab authors a steering item; every write lands on Steering. With nothing assembled, the tab is the single panel “No steering is assembled for this agent” with Open the library.
7. **Toolbelt.** Belt computation (the wire from grants, delegation ceiling, policy bundle, and kill switches to the belt; the active policy and deny generation), Model view (Searchable belt / Full belt with `aria-pressed`; the width stated against the full-belt limit; the verbatim tools block with the machine-readable trailer), Belt search (the five example queries, Run; a miss states whether the tool exists in the registry and why it is off the belt), Per-tool decision rules (By category / Flat, What the categories mean): Tool · Category · Decision · Hazard · Egress · Financial · Schema digest; Off the belt (Tool · Reason, badged “not visible to the model”). The belt search never returns a tool outside the belt. The presentation toggle changes nothing about how the agent runs and resets when another agent is opened.
8. **Runtime.** Host (Runtime · Harness · Device key · Collector · Hook binary · Hooks written · Model proxy · Oxagen MCP endpoint · Settings · Tier earned · First frame · Last checkpoint; the health badge and Open the runtime), read from the runtime record: open the same host on Runtimes and confirm the collector, the hooks, and the checkpoint are the same values, not a second copy. What this tier delivers (the four-rung ladder with “this agent” on the earned rung and no rung marked not yet available; Model calls · Tool calls over MCP · Harness-native tools · Budgets · Steering · Credentials held by this agent; the note verbatim; All runtimes). Unenroll this host from the CLI (the unenroll command, the Hooks removed note, Run a test session, Unenroll). An agent with no host enrolled gets the empty state with Enroll a runtime and Show CLI steps.
9. **Permissions.** Roles (the ∩ formula; each role with its permission ids; Resource scope · Spend ceiling · Can move money; Assign a role; the closing note that assigning a toolbelt grants nothing). Budgets (a per-run meter and a per-day meter; Mode · On a breach · Delegation ceiling; the subtext that budgets are checked at hook boundaries on reported spend and fail open, and that the proxy enforces before the call on `gateway` and `contained`; Set budget). Mandates held (Mandate · Effect · Per call · Per period · Remaining · Expires · Status; a row opens the mandate page) or No mandate with the four-step denial chain and Request a mandate. This tab never lists tools.
10. **Activity.** Runs (Run · Status · Tokens · Cost · Frames · Started; the empty panel offers Open the audit record; no Verdict column). Token accounting (Class · Tokens 30d · Rate · Cost, plus the Tool definitions row counted as input; the cache hit rate and the tool-definition share). Last 30 days (Runs · Spend · Productive ratio · Tokens; findings with Evidence and Fix; Open on Spend). Tamper incidents (one panel per incident with What happened · What it stopped · Closed or Owner · Incident; Open on Audit) or the empty panel with the detector list and Open the incident register; the count equals the Audit page’s.
11. **Definition in git.** Identity · Model and budget · Tools · Instructions · Harness, then Source (Repository · `definition_digest` · At commit · Generated beside it; Open in the source editor) and Changing this agent (the four steps and the deletion note). The bar above the split reports a parse error, unsaved changes with the diff stat, or a pending branch with its pull request; Save changes and Open a pull request both open the commit dialog; Discard reverts the draft. Nothing on this tab writes to Postgres.
12. **Actions, dialogs, and data sources.** Every button in the spec exists and opens what the spec says (`avatar`, `delagent`, `identity`, `assignrole`, `budget`, `mandate`, `tool`, `toolcats`, `evidence`, `fix`, `commit`, `register` from an unenrolled Runtime tab, `request-access` from denied, `incident` from error), and each write is a governed action: it passes IAM, produces an audit event, and shows a receipt or reference. A stub must say what the product would do; a control that silently does nothing is a FAIL. Then, for each row of the spec’s data-source table, find the adapter or query that feeds it: ✅ rows wired to the named store; 🟡 rows wired for the fields that exist and rendering `NotBacked` (never a zero) for the rest; ❌ rows rendering `NotBacked` with the gap named. Toolbelt assignments, mandates, token classes, and findings are ❌ today. A fixture reaching production is a FAIL, and coaching must be derived from the token rollup at read time, never stored as a model’s text.
13. **States.** Force each state and compare copy and controls with the design file:
    - **empty** (`state=empty`): “This agent has never run”; registered and enrolled, no frame yet; the belt is computed at run start so there is nothing to show for tools either. Action: Back to Fleet.
    - **loading** (`state=loading`): the shell stays and the body is the skeleton; no data, no zeros, no stale rows.
    - **error** (`state=error`): “This agent could not be loaded”; `503 iam_principals_unavailable`; nothing was changed; runs kept recording; frames are written by the collector on each host. Actions: Try again, Open an incident; a trace id, region, and timestamp line.
    - **access denied** (`state=denied`): “You cannot see this agent”; the missing permission `agent.read on core-platform`; an owner can grant it and the grant is a governed action. Actions: Request access, Back to Fleet. Below: Signed in as, Needed, Decided by (`pol_v41` · deny wins over every allow).
    Loading must not flash zeros. Error must name the code and offer Try again and Open an incident. Denied must name the missing permission and offer Request access.
14. **Trust language and token figures.** Every tier, replay grade, attestation, health verdict, and cost basis shows the recorded value; search the build for any place a stronger word could be rendered than the record allows (`observe`, `harness`, `gateway`, and `contained` are each shown only where recorded; only `contained` is described as enforced; a self-reported token figure says so in its Basis line; nothing says proven, score, or percentile). Money always carries its basis. The 30-day token use total equals the sum of its eight bars; the Token accounting rows on Activity sum to the same total; the agent’s row on Agents shows it too; each coaching item’s tokens and dollars derive from that rollup (recompute one and compare). A constant or a typed figure is a FAIL.
15. **Words, headings, mobile, accessibility, permissions, and nothing extra.** The page uses Agent, Principal, Toolbelt, Runtime, and Assignment, and nowhere says “Agent IAM”, “service account”, or “enrollment” as the name of a place. No heading carries a comma, a mid-dot, or a not/never contrast; subtext under a heading is one sentence. At 390 × 844 with a touch pointer: the five-slot thumb bar is present, the two Overview panels stack, the tab strip scrolls in its own row and keeps the selected tab in view, the definition split becomes one column, every dialog is a bottom sheet with full-width footer buttons, every table renders as labelled cards, the page never scrolls sideways, every tap target is ≥ 44 px, inputs are 16 px. Tabs use `role=tablist/tab` with `aria-selected`; dialogs are `role=dialog aria-modal` with a labelled close; the tier ladder is an ordered list with `aria-label`; the belt presentation and layout toggles carry `aria-pressed`; icon buttons have `aria-label`; state is never colour alone (dot + word); focus is visible; the page is operable by keyboard end to end. Read requires `agent.read`; each write (`agent.credential.rotate`, `agent.credential.revoke`, `agent.suspend`, `agent.deregister`, `agent.role.assign`, `budget.set`, `enrollment.revoke`, `agent.write`) is gated server-side, verified with a role that lacks the permission. Then list anything on the built page that is not in the spec (panels, tabs, columns, buttons, copy); each is a finding and the reviewer decides whether it stays.
