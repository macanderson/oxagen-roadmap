    Design reference

    Colors

    The app surface is dark first, on obsidian, with a white light theme that carries the same roles. The greys are neutral zinc with no hue, so gold is the only warm value on a screen. Color never carries a state alone: a word or a shape carries it too.

    Source mockups/src/engine.css lines 1 to 46 Brand oxagen-branding/assets/tokens.css Contrast WCAG 2.2, computed on load

    Principles

    Six rules decide every color on the surface.

    1. Tokens only.

      Every color is a var(--token) from engine.css. A hex value in a component is a defect, because it cannot follow the theme.

    2. Neutral grounds.

      Grounds, borders, and text are zinc greys with no hue. The data and the one action carry the color.

    3. Gold is identity.

      Gold marks the brand, the first eyebrow, the focus ring, and at most one action per screen. It never carries a state, fills a surface, or highlights a row.

    4. Every word clears 4.5:1.

      Text a person needs to read or act on clears 4.5:1 on its ground. Large text (24px, or 18.66px at 700) and interface marks clear 3:1.

    5. State by word and shape.

      A badge carries its word. A verdict card carries its border shape. Color is the third signal, never the only one.

    6. Both themes, always.

      Every token has a dark and a light value. A component that looks right in one theme only is unfinished.

    Gold

    Gold is the brand's identity, and each screen spends it once.

    Gold may mark
    • The two lit cells of the hive, the x of oxagen, and the asterisk of stella
    • The first eyebrow on a page
    • The focus ring (:focus-visible) and a focused input's border
    • One primary action per screen: .btn.primary, with --on-gold text
    Gold never marks
    • A state, a verdict, or a count
    • A surface fill, a card border, or a table row
    • A paragraph, a heading, or a link
    • A second action on the same screen

    AvoidTwo gold actions. The screen no longer says which one matters.

    UseOne gold action. Every other button is neutral.

    Gold on white is 2.1:1, so gold set as text in the light theme is --gold-deep (4.65:1 on white). --accent-text resolves to the right one in each theme. Use it, and never pick the shade by hand. A gold fill keeps its metal in both themes and takes --on-gold text (9.5:1).

    Theming

    Three token blocks set the two themes.

    1. :root holds the dark values, the default.
    2. @media (prefers-color-scheme: light) on :root:not([data-theme="dark"]) follows the operating system.
    3. :root[data-theme="light"] pins light, and data-theme="dark" pins dark. The mockup reads ?theme=, and so do these pages.

    The two light blocks must stay identical. Today they are. A token added to one and not the other shows the wrong theme to half the people who choose light.

    Findings

    Where the mockup departs from these rules today.

    contrastQuietest grey on words a person needs

    --dim sets table headers (th) and stat labels (.stat .k), and 155 rules use it as a text color. On --panel it is 3.67:1 in dark and 2.56:1 in light. Table headers and stat labels are words a person reads to act, so they belong on --muted (6.91:1 dark, 4.83:1 light).

    contrastFailure red as small text in dark

    --st-failed is 3.94:1 on --ink and 3.51:1 on --panel in dark. 20 rules set it as text, .btn.danger among them. The brand kit's destructive red (#D5584D dark, #992F28 light) clears 4.5:1 both ways, and engine.css has no --destructive token.

    contrastBadge words on their tint

    The 11% tint lifts the ground a badge sits on, so its word loses contrast. On --panel in dark, denied is 4.15:1, critical 3.69:1, and failed 3.21:1. In light, allowed is 4.36:1. Badge words are 11px, so each needs 4.5:1. State colors computes the current values.

    contrastSecondary text on light grey bands

    In light, --muted is 4.40:1 and --accent-text 4.23:1 on --hl, --void, and --panel-h. Subtext inside a shaded panel header falls just short.

    goldGold beyond identity and one action

    80 rules in engine.css use gold. Beyond the focus ring, the primary button, and the marks, gold also draws the selected tab's underline, the current nav item and pager page, pressed toggles, unread markers, checkbox accents, search marks, and the left rule of .note and .callout. Each is a state or a highlight by the brand's rule. Moving them to --fg or --rule is a design decision for Mac.

    noteHex values outside the tokens

    The engine names a hex value directly in a few places, so those colors do not follow the theme. The debug chrome (#chrome) is one and is shown only under ?debug=true. The LOGO artwork carries #D4AF37 for the lit cells and the x, which the brand requires.

## Inputs

1. mockups/colors.html in the roadmap repo. Read it in full: the principles, grounds, text roles, approved pairs, gold rules, state and kind colors, and findings. Open it in a browser too, since its contrast matrix is computed on load.
2. mockups/src/engine.css lines 1 to 46: the three token blocks. These values are the spec.
3. The build's token files (CSS variables, Tailwind theme, or design tokens) and its theme switch.
4. Routes to sample in both themes, desktop at 1440 by 1000: Work, Agents, one agent, one run with its transcript, Spend, Steering, one dialog, one destructive confirm, the approvals drawer, and an empty and an error state.

## Procedure

Record PASS, FAIL, or N/A for every check, with evidence: a file and line, or a selector with its computed color and background (getComputedStyle), and the ratio you measured.

1. Token parity. Every token in engine.css exists in the build with the same dark and light values. List any token that is missing, renamed, or different, with both values.
2. No raw colors. Search the build's components for hex, rgb(), hsl(), and named colors outside the token files. Each hit is a FAIL unless it is brand artwork (the hive cells and the x are #D4AF37 by rule).
3. Grounds. The page is --ink, the sidebar and code wells are --void, panels and cards are --panel, panel headers are --panel-h, highlights are --hl. In light, a card is separated by its border and is never tinted.
4. Text roles. Headings and values use --fg, reading text --body, secondary text --muted. --dim appears only on placeholders, disabled text, separators, and decoration. Every other --dim text is a FAIL: list it.
5. Contrast. For every text element on every sampled route, compute the WCAG ratio of its color against its effective background, blending any translucent layer. Text under 24px (or under 18.66px at 700) must clear 4.5:1. Larger text and interface marks (icons, focus rings, input borders, meter fills) must clear 3:1. List every failure with its selector, colors, ratio, and route, in both themes.
6. Gold count. On each sampled screen, count gold elements that are not the marks, the focus ring, a focused input, or the first eyebrow. More than one is a FAIL. Gold on a state, a surface, a card border, a row, a paragraph, a heading, or a link is a FAIL.
7. Gold as text on white. In light, gold text uses the deep shade (#8A7223) through --accent-text. Bright gold text on white is a FAIL.
8. The primary action. The gold button's label is --on-gold. Its hover is --gold-bright.
9. State. Every state badge carries its word and uses its own state token on an 11% tint with a 42% border. A state shown by color alone (a colored dot or row with no word) is a FAIL. Verdict cards use border shape: double for held or allowed, dashed for pending, single for broken or denied.
10. Destructive. Destructive buttons and error text clear 4.5:1 in both themes. The mockup's --st-failed as small text in dark does not (3.51:1 on --panel); report what the build uses and its ratio.
11. Kinds. Frame kinds and context kinds use the --fk-* and --k-* tokens, never a state hue and never gold. A kind badge has an icon and its word. --fk-tool, --fk-gov, and --fk-op never set text in light.
12. Theme switching. The build follows the operating system when no theme is chosen, and a chosen theme persists. The two light definitions (media query and attribute) are identical. Switching themes changes no layout and loses no state.
13. Focus. Every interactive element shows the gold focus ring on keyboard focus in both themes, and the ring clears 3:1 against the ground beside it.
