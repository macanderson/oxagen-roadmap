Tool policy

Agent policy spec

A policy decides each tool call an agent asks for: allowed, denied, or parked until a person approves it. The rules are written in Cedar, and the gateway evaluates the active version for every call routed through Oxagen, with no model in the decision. On the harness tier the hook refuses a call and fails open. On the observe tier nothing is refused, and the call is recorded.

Status: proposed. §6.12 of the mission control spec decides that tool policy is Cedar, deterministic, versioned, and tested, and ADR 0004 says why Cedar. The schema, the @decision annotation, the way Oxagen reads a denial, and the toolbelt grant below are proposed in PR 127 and on this page. None of them is decided.

26 examples and 59 tests. Every decision on this page was computed by Cedar 4.13.0 (language 4.5) through @cedar-policy/cedar-wasm, with every rule validated against the schema in strict mode. Reviewed 2026-09-25. Built by tools/build-policy-spec.mjs.

Evaluation

How a call is decided

  1. The gateway builds a request for the call. The principal is the agent, the action is the tool, the resource is what the call acts on, and the context holds the call's facts.

  2. Cedar evaluates every rule in the active version. A forbid that applies wins over every permit. When no rule permits the call, Cedar denies it.

  3. When Cedar denies a call, it names the rules that decided. If every one of them carries @decision("require_approval"), the gateway parks the call for a person. Otherwise the call is denied.

  4. When a person approves, the gateway asks again with context.approval.granted set to true. The approval rules stop applying, and the call runs only if a rule permits it. An approval never grants what no rule permits, and it never lifts a forbid that has no unless for it.

Each decision reads as a word and a shape:allowrequire approvaldeny

Every test on this page runs against the rule it illustrates plus the toolbelt grant, a permit Oxagen compiles from each agent's toolbelt. §6.12 says a version compiles from the rules written for it, the enforcement grants on each agent, and the role grants on each operator, so a grant is never written again as a rule.

Schema

The shape of the request for one tool call. Validation against it catches a misspelled path, a missing has, or an undeclared tool before a version is saved.

ContextTypeWhat fills it
context.toolToolThe tool version and the registry's classification of it: risk, side effect, egress and financial class.
context.argsArgsThe call's arguments by name. Only the ones the call carries are present.
context.taintrecordWhether any input to the call came from an untrusted source, and which sources.
context.timerecordThe gateway's clock, in UTC, when the call arrives.
context.raterecordHow many calls of this tool the agent made in the last hour and the last minute.
context.runrecordThe tools already called in this run, and the objects already read in it.
context.operatorrecordThe role of the operator the run works for.
context.tierStringThe enforcement tier computed for the run: observe, harness, gateway or contained.
context.budgetrecordWhat the run's budget has left, in cents.
context.mandaterecord, optionalWhat the mandate the call draws on has left, when the call draws on one.
context.approvalrecordWhether a person approved this call, and how many people did. The gateway sets it when it asks again after an approval.
// The request Oxagen's gateway builds for one tool call.
entity Workspace;

// An agent belongs to one workspace. Its toolbelt lists the tools it is granted.
entity Agent in [Workspace] {
  toolbelt: Set<String>
};

// What a call acts on: a repository, a connection, a cluster.
entity Target;

// The tool version, as the registry classifies it.
type Tool = {
  name: String,
  version: String,
  risk: String,
  side_effect: String,
  egress: String,
  financial_class: String
};

// The call's own arguments. Each is optional, so a rule tests it with has first.
type Args = {
  amount_cents?: Long,
  counterparty?: String,
  repository?: String,
  branch?: String,
  path?: String,
  channel?: String,
  recipient_domain?: String,
  cluster?: String,
  schema?: String,
  fields?: Set<String>
};

type Call = {
  tool: Tool,
  args: Args,
  taint: { tainted: Bool, sources: Set<String> },
  time: { hour_utc: Long, weekday: Bool },
  rate: { calls_last_hour: Long, calls_last_minute: Long },
  run: { prior_calls: Set<String>, prior_reads: Set<String> },
  operator: { role: String },
  tier: String,
  budget: { remaining_cents: Long },
  mandate?: { remaining_cents: Long },
  approval: { granted: Bool, approvers: Long }
};

Mistakes

Patterns to avoid

Each problem below is shown by Cedar itself: the parser, the validator, or a decision the author did not mean.

An optional argument read without has

An argument a call may not carry has to be tested with has before it is read. The validator refuses the rule otherwise.

@id("avoid.no-has")
@decision("require_approval")
forbid (principal, action == Action::"stripe__create_refund", resource)
when { context.args.amount_cents > 50000 }
unless { context.approval.granted };
Validation errorfor policy `avoid.no-has`, unable to guarantee safety of access to optional attribute `args.amount_cents` in context for Action::"stripe__create_refund"

Written correctly in Refunds above $500.

A context path the schema does not hold

A misspelled path is a validation error, so the rule never reaches a version.

@id("avoid.unknown-path")
@decision("require_approval")
forbid (principal, action, resource)
when { context.tool.side_efect == "irreversible" }
unless { context.approval.granted };
Validation errorfor policy `avoid.unknown-path`, attribute `tool.side_efect` in context for Action::"github__create_release" not found

Written correctly in Irreversible calls.

An effect Cedar does not have

Cedar has two effects, permit and forbid. A rule that needs a person is a forbid with @decision("require_approval").

@id("avoid.third-effect")
permit (principal, action, resource)
when { context.tool.side_effect == "irreversible" }
advice "require_approval";
Parse errorfailed to parse policy with id `avoid.third-effect` from string: unexpected token `"require_approval"`

Written correctly in Irreversible calls.

An approval rule with no unless

Without unless { context.approval.granted }, the rule still applies after a person approves, so the call never runs.

@id("avoid.no-unless")
@decision("require_approval")
forbid (principal, action, resource)
when { context.tool.side_effect == "irreversible" };

github__create_release@2a-intel.core.release-managerapproveddenyavoid.no-unlessrequire approval
