Every view, every source

Fourteen mockups draw the ten pages of Mission Control. This traces each view, each state it can be in, and each number on its face back to the thing that produces it: the fixture in the mockup, the table or frame the specification names as its source of truth, and whether that source exists in code today.

Three answers come out of it. Which surfaces are drawn but have nothing behind them. Which numbers are typed into markup and cannot be restated. And which parts of the specification have no surface at all. Twenty-five defects found along the way are fixed on the same branch, and the last section says what they were and what was left alone.

Five

Numbers with no source

Figures typed into markup, and figures whose label claims a basis the mockup cannot produce. These are the ones that will not survive contact with real data, because nothing computes them.

Twenty-three of these are now fixed. Everything described below as a contradicting total, a stated-but-uncomputed formula, or a mismatched identity has been made derived on this branch, so the number and the rows under it can no longer drift apart. Rows carrying a FIXED on this branch note in the table above are the ones that changed. The subsections below keep the original finding, because the reasoning is what makes the next one recognisable. What stays open is listed at the end of each subsection.

Figures typed where the caption states a formula

Each of these prints the formula beside a number that the formula did not produce. The specification names the inputs and they exist in the fixtures.

  • Fleet cache hit rate, 81 per cent. The caption gives the formula as cache reads over uncached input plus cache reads. Every run carries a cache figure. None is aggregated.
  • Agent detail cache hit rate, 78 per cent. Reads a cache field on the agent record or falls back to 0.78. Agent records have no cache field, so it is always the fallback.
  • Audit median time to resolve, 2h 38m. The five resolved incidents carry opening and closing times. Their median is 1h 22m and their mean is 1h 3m.
  • Policy simulation, about 37 a day and 96.8 per cent of calls. Both read as derived from the counts beside them, and both are strings that happen to match.
  • Billing this period. The run count, the per-run price and the discount rate are all present, and the three amounts are stored. Nothing multiplies or subtracts.
  • Run cost detail. One token breakdown with its cost in micro-USD is printed for every model response frame, including two whose own summaries give different token counts.

Claims of a basis with nothing behind them

The specification's interaction rule is that every badge describing trust shows the recorded value and nothing stronger, and every money figure shows its basis. These assert a basis that no record supplies.

  • The no-gaps badge on the chain tab is unconditional. It shows whatever the run's replay grade, beside a completeness-gap line that degrades to a typed three.
  • Chain position 27 of 31, verified. A fixture string. Nothing verifies, and the Verify button on an export reveals a pre-written transcript.
  • gateway_observed as a basis chip is hard-coded on the Spend header, on every model row, on the tool table header and under Fleet's spend tile, including where one run in the same total is client-attested.
  • Settled this period, from the ledger. Reads a stored figure; the ledger printed beside it is four hard-coded rows that add to it by hand.
  • A Stripe charge for $18.00 with no receipt, presented at severity critical as money Oxagen did not govern, and repeated in five places. No record of it exists in any fixture.
  • Rounded to cents once, half-even. The total is stored. No rounding happens.
  • Blast radius on all ten kill switches is free prose asserting counts of tool versions, agents, mandates and runs in flight, reprinted as fact in the confirmation dialog and again in the banner after a flip.
  • Fabricated digests. Frame hashes are arithmetic on the sequence number. A tool's schema digest on approval comes from the length of its name. Commit-draft telemetry, presented as usage from a named model at a named tier, is three formulas over the diff size.

Two measures that render as one number

The subtlest class, and the one most likely to survive into production. Productive ratio counts steps that advanced the task. Proven spend counts runs whose witness verdict flipped. They are different measures, and the mockup shows them as the same figure.

  • At organization level the productive ratio reads 43 per cent, and proven divided by spend is also 43.0 per cent.
  • On an operator drill-down, the productive ratio tile and the proven spend tile's sub-label both read 55 per cent, side by side in one row of four.
  • On Agent detail the proof rate is computed by multiplying the run count by the productive ratio, and labelled as runs flipped. That agent has no flipped run at all. Cost per proven flip and business value both inherit the error.

This was the one to fix before the numbers became real, and it is fixed. The other defects were wrong values that a real query would replace. This one was a wrong definition that a real query would have faithfully implemented, because the label and the formula disagreed and only the label was visible. Agent records now carry a flipped-run count of their own, the two agents with no proven spend carry zero, and the productive ratio has its own row beside the proof rate.

What stays open

These were left alone deliberately. Each needs a decision rather than a patch, and inventing a number would be worse than leaving the one that is there.

  • The fixture is five agents deep against a fifty-agent story. The workspace agent count is a real field and stays, but no 30-day figure can be derived from five records. Deepening the fixture is a content decision.
  • Cross-cut spend contradicts itself by direction. Each entity's breakdown sums exactly to its own spend, yet the same dollar appears once as a named tool and once as unattributed when read the other way. Fixing this means rebuilding the spend fixture as one matrix rather than per-entity lists.
  • The reconciliation variance is attributed to an agent whose total spend is a third of it, and a notification reports a different variance for the same mechanism. Which story is right is a product decision.
  • Two of three invoices do not follow the page's own price list, and the retention price differs between two pages by a factor of a hundred. Both need someone to say which figure is correct.
  • Frame-level detail panels print one record's values for every frame. Fixing this means giving each frame kind its own body in the fixture, which is a larger content pass.
  • The run summary says 38 pull requests where everything else says 27. A one-word change, but it is demo narrative rather than a derivation, so it belongs with whoever owns the script.

Surface with no specification, which is the inverse gap

Three things are drawn, wired to fixtures, and load-bearing in the demo, while the specification defines nothing behind them. These will be built because they are on screen, unless someone decides otherwise.

  • A numeric agent trust score and spend score. Shown as pills on Fleet rows, approval cards, the Agents list, Agent detail and the mandate grant panel. Auto-approval rules gate on minimum trust and minimum spend thresholds. The specification's auto-approval conditions are a measure under a threshold, an allow list, mandate position, a standing approval, absence of taint, and business hours. No score appears anywhere in it, and the specification's own rule is that a badge describing trust shows a recorded value.
  • An auto-approvals tab with three rules, an editor, a live qualifying-agent preview, and a claim of fifty-five historical auto-approvals. Auto-approval exists in the specification as a kind of policy rule, not as its own registry with its own scoring.
  • A wasted-spend tab with six causes and a per-run waste share. The specification ranks findings by money at stake; it defines no waste total, no waste share and no per-cause breakdown.

States the chrome offers and no page implements

  • The agent source editor has no load-state branch at all. Switching to empty, loading, error or denied leaves the editor fully rendered.
  • The phone state is CSS only. No page, panel or dialog has a behavioural branch on it, so there is no one-thumb navigation anywhere, which is the third item of the review feedback on this set.
  • Registration and all ten welcome screens have no empty state, and several carry neither an error nor a denied branch.
  • The assistant's engine-down state is complete and unreachable. Nothing sets it; only the Retry button that clears it.
  • Unknown routes render Fleet silently. There is no not-found state.
  • The shared denied panel names a different person than the one signed in, on every page that can show it.

What this pass fixed

Twenty-five defects, in three groups. Every change was driven in a headless browser across the affected routes, with no script errors.

Two functions were declared twice, so the later one won by hoisting

  • The record kind badge was dead. A second function of the same name, written later for identity role kinds, took over the records page. Every Steering record and proposal card rendered a plain grey chip with a bare word, losing the six-kind icon badge and its tooltip that the statement-first card design is built around. The role version is now named for what it does, and all seven cards render their badges again.
  • A timestamp parser lost its guard. Two parsers shared a name; the looser one won, so the proof tab's flip-timing calculation lost the null check protecting it against a malformed timestamp and would have printed a non-number. Each caller now gets the parser it was written against.

No duplicate top-level function name remains. One command catches the whole class, and it is worth running before any edit to this file, because everything lives in one script:

rg -o '^function ([A-Za-z_$][A-Za-z0-9_$]*)' mc.html -r '$1' | sort | uniq -d

Fourteen figures that stated a formula now run it

  • The proof rate is no longer the productive ratio. The single most consequential fix, for the reason given above.
  • Both cache hit rates derive. Fleet spend-weights the runs it is showing; the agent strip reads its 30-day rollup. Each says plainly when nothing records the figure, instead of printing a constant.
  • Spend per proven run derives from a flipped-run count on both the agent strip and the spend rollup, so it can never again equal spend per run.

  • Wasted spend share and approvals overturned derive, replacing two hard-coded percentages and an invented denominator.
  • The denied panel names the person who is signed in. It was naming someone else while the top bar showed the real user. There is now one session accessor.
