01

Overview

What the in-app agent becomes, and the rules it keeps.

Target

stella in the app does what stella in the terminal does, plus what the capability roadmap asks for that the terminal lacks: evidence-linked answers, deterministic charts, durable artifacts, action plans applied by digest, and distribution with receipts.

Parity definition

A 30-task bench (S05) runs each task through both agents on the same model. The in-app verdict rate lands within 5 points of the terminal's, and steps and cost land within 1.25 times. Pass rate alone saturates, so steps, cost, and interventions are scored too.

Source of the sandbox

Neither source document asks for a sandbox. It comes from the parity goal and from the maintainer's decision on 2026-09-25 that stella gets contained sessions. Section 04 has the design, and D1 records it as an ADR.

Rules that hold in every phase

  • The engine holds no authority. stella-serve never calls a model or runs a tool. STELLA_SERVE_TOOLS accepts only remote (crates/stella-serve/README.md). Every model call and tool call comes back to Oxagen.
  • Every effect is a contract. A file write, a shell command, a chart render, and a pull request each run through kernel.invoke() with IAM, entitlement, approval, and metering, and each leaves a frame on the turn's run.
  • No runtime grows back. ADR-043 deleted Oxagen's sandbox, sub-agent, web, and artifact packages because Stella owns them. The tools here are Stella's own code, and sub-agents run inside the engine. Oxagen adds gates, a driver, and stores.
  • No key enters the agent. A GitHub installation token never enters the engine or the sandbox (ADR-151). Clones come through a short-lived archive URL or a host proxy, and commits are written host-side.
  • Any agent can call the new families. Oxagen governs Claude Code and Codex too. Each new family ships on the agent, api, and mcp surfaces, so stella is the first caller and not the only one.
  • AWS only. Nothing on the path depends on Vercel, and the app host has no Docker. Production artifact storage moves off the Vercel Blob driver in @oxagen/storage.

04

Containment

How a stella session earns the contained tier.

contained is the top of the tier ladder (ADR-095: observe, harness, gateway, contained) and the only tier that earns "enforced" against the machine's operator. It is built for Claude Code and Codex as tacho run --contained with the Docker profile oxagen-linux-docker-v1 (ADR-152, packages/tacho/src/contained/). A sandbox alone does not earn it. ADR-096 requires three controls, and the control plane computes the tier from a launch receipt and the run's record. A launcher never labels its own run.

1Egress

Customer harness: every model and MCP request goes through the gateway or fails. stella session: nothing leaves the microVM. The engine runs outside it, so there is no model route and no MCP route. The one channel is the tool host's socket to Oxagen. A repository arrives as an archive the host fetched.

2Filesystem policy

Customer harness: the workspace is writable and the hook config is read-only. stella session: the session workspace is the only writable path. The tool host binary and its config are read-only, and no credential file enters.

3Integrity at launch

Customer harness: a digest of the hook configuration is recorded. stella session: the image digest and the tool host digest are recorded on a launch receipt before the first tool call, the way register_contained_launch records one today.

Why a stella session is stricter than a wrapped harness

In a wrapped harness the agent's own tools run inside the sandbox, so a hook is the only thing that can refuse them. ADR-096 pins the hooks read-only to close that gap. stella's tools never run on their own. The engine asks, Oxagen gates the call through kernel.invoke(), and only then does Oxagen send it into the session. Refusal happens before the sandbox sees anything. The sandbox then bounds what an allowed call can reach.

Limits. ADR-152 states what the tier does not cover, and the stella profile inherits the same limits. Enforcement holds against the agent and every process it starts, not against whoever administers the host. For stella that administrator is Oxagen's own operations. The receipt is a launcher attestation with no hardware signature. A microVM holds against a stronger escape than a container does. Neither boundary changes what a host administrator can do.
