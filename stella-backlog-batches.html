4. Fix. Give each lane a worktree at `~/Projects/.worktrees/stella/<lane>` on branch `backlog/<lane>`, cut from `origin/main`. Work the lane's issues in the order listed, one fresh agent per issue, on the model its `use-model` label names: cheap on Haiku, balanced on Sonnet, pro or no label on Opus, and ultra on Opus at max effort. Before each issue, run `./scripts/issue-claim.sh claim <n>` from the lane's worktree, which gives each lane its own claim identity, and skip the issue if the script stands you down. When the scout found an issue already fixed on `main`, the commit adds the missing witness test and closes it. When the scout flagged a decision, comment the question on the issue and skip it.
5. Local checks. Run `cargo fmt --check`, `make guards-fast`, and at most one crate with one test filter, such as `cargo test -p stella-core loop_detect`. 7. Review. One adversarial reviewer per PR, on Opus. It tries to refute each fix: the witness test must fail on the parent commit, the diff must stay inside its issue, and no `#[allow]` without a reason or `unwrap` on runtime data may enter. The lane's fixer answers each finding on the same branch.
8. Watch. One watcher per PR reads its state, mergeability, and the checks on the head commit every 60 seconds until it merges or closes. On a failed job, read `gh run view --job <id> --log-failed`, fix it, and push. On a conflict, merge `origin/main` in, resolve it, and push. Settle every Sourcery ❌ row with a commit or a PR comment. A cancelled or skipped required job counts as not passed. When the review has passed and every required check is green, run `gh pr merge --squash --auto`.
9. Report. A final agent lists every issue in this batch with its PR and state, or the reason it has none. File anything you could not fix as a new issue with the `triage` label and no other label.

How the lanes were built

Method

  1. 1

    Every open issue was read from GitHub at 17:23 PDT on 2026-09-25, with its labels and body. Three open PRs existed then.

  2. 2

    Epics, question labels, blocked labels, titles that ask for a decision or a measurement, and issues that need spend or credentials went to the held list.

  3. 3

    The rest were grouped into lanes by the source files their bodies name, so one agent fixes related issues on one branch. A lane holds three to ten issues.

  4. 4

    Two lanes share a batch only when their bodies name no common file, apart from the four stella-cli hub files, which at most two lanes per batch may share. A batch holds at most six lanes, because the merge queue, not agent count, sets the pace.

  5. 5

    A file named in an issue body is a prediction of what the fix edits. The scout stage in each prompt re-reads the code on main and holds a lane back when the prediction was wrong.

  6. 6

    Model choice follows each issue's use-model label: cheap on Haiku, balanced on Sonnet, pro or no label on Opus, and ultra on Opus at max effort. Reviewers run on Opus. This mapping is a proposal in these prompts, and the tier names come from Stella's triage taxonomy.

  7. 7

    Each watcher arms squash auto-merge once review passes and every required check is green. Delete that sentence from a prompt to merge by hand.
